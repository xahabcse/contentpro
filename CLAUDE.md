# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Conventions that apply to **all** work in this directory. This repo (GitHub: `xahabcse/contentpro`) has two things in it:

1. **Today:** a Claude-driven, code-only pipeline for designing **LinkedIn posts** (copy + graphics) — `templates/`, `scripts/render.js`, `posts/<slug>/content.json`. See **Purpose & Workflow** below.
2. **In progress:** evolving into **ContentPro**, a self-service multi-tenant web app where end users register and create/edit/export their own LinkedIn card/carousel designs — no Claude/CLI involved for end users. Full requirements spec: **`docs/contentpro-spec.md`**. The `app/` (React/Vite frontend) and `api/` (Hono/Cloudflare Workers backend) folders it describes don't exist yet — see **ContentPro Web App** below for the specialist agents/skills/CI already scaffolded ahead of that build.

## Purpose & Workflow

- **Goal:** produce **reliable, professional** LinkedIn posts — consistent, polished, publish-ready.
- **Input → output:** the user provides a **content link** (article / blog / docs). From that source, produce the post — copy + graphics, in one of two formats (see `brand/brand-kit.md` → Formats): **A — Single Card** (short/hot news) or **B — Carousel** (deep-dive topic).
- **Design engine:** **code, not a GUI tool.** HTML/CSS templates in `templates/`, rendered to PNG/PDF by Playwright (`scripts/render.js`) — see **Rendering Commands** below. This replaced Canva as the primary engine because Canva's MCP couldn't insert new text elements or crop images to a circle; raw HTML/CSS has neither limitation.
- **Quality bar:** accuracy first — don't invent facts beyond the source; keep visual/brand style consistent across posts (enforced by construction, since every post reuses the same templates).
- **Brand style:** every design follows **`brand/brand-kit.md`** — the single source of truth for colors/fonts/layout, and it now maps 1:1 to the literal CSS in `templates/`.

## Rendering Commands

```bash
# Render a post (auto-detects Format A "card" vs Format B "carousel" from content.json)
node scripts/render.js posts/<slug>

# Example
node scripts/render.js posts/2026-07-http-query-method
```

- Create a new post: make `posts/<slug>/content.json` (schema + examples in `brand/brand-kit.md` → Rendering Pipeline), then run the command above.
- Output lands in `posts/<slug>/output/`: `card.png` for Format A, or `carousel.pdf` + `page-NN.png` per slide for Format B.
- One-time setup already done in this repo: `npm install` (installs `playwright` + `sharp`) and `npx playwright install chromium`. Re-run `npm install` only if `node_modules/` is missing (it's gitignored).

## Working Rules (autonomy · identity · attribution)

1. **Autonomy — run freely, ask only before deleting.** Work end-to-end without pausing for permission on normal commands (PowerShell, cmd, git, grep, npm/npx/node, curl, gh) and on Read/Write/Edit/Glob/Grep/WebFetch/WebSearch — this is wired in `.claude/settings.local.json` (broad `allow` + delete-only `ask`). The one hard gate: **confirm before DELETING any file or data** (`rm`, `Remove-Item`, `del`, `rmdir`, `git clean`, `git reset --hard`, `git rm`, `find -delete`, etc.) — even if a particular delete path slips past the `ask` rules, stop and ask first.

2. **Identity for forms / configs / placeholder data.** When a name or email is required anywhere (config field, form, sample author), use **`Md Sahabuddin Hossain`** / **`sujoncep@gmail.com`**. This is NOT about git commit author (leave git config as-is). For live mail-service testing, the global "ask which address first" rule still applies.

3. **Git commit rules — zero AI attribution.** Commit messages and PR bodies must be clean:
   - ❌ Never add a `Co-authored-by:` trailer
   - ❌ Never add `Generated by` / `Generated with` / "🤖 Generated with Claude Code" or any similar attribution

   Write only the real change description (Conventional Commits style: `feat()`, `fix()`, `docs()`, etc.). Attribution is also disabled at the tooling level via `attribution.commit`/`attribution.pr` in `.claude/settings.local.json`.

4. **Playwright artifacts go in `.playwright-mcp/`.** The playwright MCP is configured with `--output-dir .playwright-mcp` (see `.mcp.json`), so **pass a BARE filename** to `browser_take_screenshot` (e.g. `post-preview.png`) — never add a `.playwright-mcp/` path prefix yourself (a bare name leaks to the repo root, a prefixed name double-nests).

## ContentPro Web App

Specialist subagents, slash-skills, and CI/CD for the web app described in `docs/contentpro-spec.md` are already scaffolded, ported and adapted from the "learning" (Porhi) project's tooling for this project's actual stack (Cloudflare D1; email+password + PBKDF2, not Google OAuth; no dev branch). Content-authoring-specific agents/skills from that source project (course/MCQ/handbook writers) were **not** ported — irrelevant here.

### Agents (`.claude/agents/`)

| Agent | Use for |
|---|---|
| `cf-api-engineer` | Backend work under `api/` — Hono routes, D1 data access (`lib/db.ts`), the `RateLimitDO` Durable Object (atomic auth throttling), PBKDF2/JWT/Turnstile/Resend, R2 access, `wrangler.toml`. |
| `app-engineer` | Frontend work under `app/src/` — components, routes, the Card/Carousel live editor, the client-side PNG/PDF export pipeline, and design/UX audits against `brand/brand-kit.md` tokens. |
| `release-engineer` | Ship/deploy mechanics — push to `main`, CI status, Durable Object migration ordering, R2/secrets setup. Does not write feature code. |
| `ui-tester` | Live-browser QA via Playwright MCP against ContentPro's real screens (signup → editor → download). Read-only; reports bugs, doesn't fix them. |

### Skills (`.claude/skills/`, all `user_invocable`)

| Skill | Purpose |
|---|---|
| `/deploy` | Ship to production — push to `main` (no dev branch), CI deploys automatically. |
| `/setup-secrets` | Set Cloudflare Worker secrets (`JWT_SECRET`, `RESEND_API_KEY`, `TURNSTILE_SECRET_KEY`, `CLOUDINARY_API_SECRET`) + GitHub Actions secrets. Run once per new account/rotation — **user supplies the real key/token values.** |
| `/build-check` | Production build sanity check for `app/` before committing/deploying. |
| `/ui-test` | Interactive Playwright QA run (the human-invokable counterpart to the `ui-tester` agent). |

### CI/CD (`.github/workflows/`)

`deploy-api.yml` and `deploy-app.yml` trigger on push to **`main`** (path-filtered on `api/**` / `app/**`) — typecheck/build first, deploy only if that passes. **No `dev` branch, no auto-merge-PR bot** (a deliberate simplification vs. the Porhi project's flow) — deploy directly from `main`.

| Server | Purpose |
