## Legacy post workflow

- **Goal:** produce **reliable, professional** LinkedIn posts — consistent, polished, publish-ready.
- **Input → output:** the user provides a **content link** (article / blog / docs). From that source, produce the post — copy + graphics, in one of two formats (see `brand/brand-kit.md` → Formats): **A — Single Card** (short/hot news) or **B — Carousel** (deep-dive topic).
- **Design engine:** **code, not a GUI tool.** HTML/CSS templates in `templates/`, rendered to PNG/PDF by Playwright (`scripts/render.js`) — see **Rendering Commands** below. This replaced Canva as the primary engine because Canva's MCP couldn't insert new text elements or crop images to a circle; raw HTML/CSS has neither limitation.
- **Quality bar:** accuracy first — don't invent facts beyond the source; keep visual/brand style consistent across posts (enforced by construction, since every post reuses the same templates).
- **Brand style:** the legacy templates follow **`brand/brand-kit.md`**. The web app's current theme tokens are in `app/src/styles/tokens.css`.

## Rendering Commands

```bash
# Render a post (auto-detects Format A "card" vs Format B "carousel" from content.json)
node scripts/render.js posts/<slug>

# Example
node scripts/render.js posts/2026-07-http-query-method
```

- Create a new post: make `posts/<slug>/content.json` (schema + examples in `brand/brand-kit.md` → Rendering Pipeline), then run the command above.
- Output lands in `posts/<slug>/output/`: `card.png` for Format A, or `carousel.pdf` + `page-NN.png` per slide for Format B.
- One-time setup already done in this repo: `npm install` (installs `playwright` + `sharp`) and `npx playwright install chromium`. Re-run `npm install` only if `node_modules/` is missing (it's gitignored).

## ContentPro Web App

The web app is implemented under `app/` and `api/`. Its account and profile data use Cloudflare D1, profile images use private R2, and designs stay in account-scoped browser storage. `docker compose up --build` runs D1 and R2 locally, but the build, Google Fonts, Turnstile widget, and login/signup verification require internet access. Node.js 24 is used in Docker and CI. See `README.md` for setup and limitations.

### Admin lives at admin.xahabcse.me (since 2026-11-14)

Cardstock has no admin UI of its own any more. One admin at **admin.xahabcse.me** (portfolio repo, `Web/portfolio-admin-react`, pages under `src/pages/cardstock/`) runs the portfolio, NewsPortal and Cardstock. Standing rules: `D:\Exp-Work\protfolio\docs\rules\unified-admin.md` (the finished plan is in the portfolio repo's git history: `git show 77f5466:docs/plan/unified-admin.md`).

- **How it reaches Cardstock:** the portfolio API (`portfolio-api-hono`) checks the admin's own login, then calls this Worker over a Cloudflare service binding to the named entrypoint `AdminGateway` (`api/src/index.ts` → `api/src/admin-gateway.ts`), sending `X-Admin-Actor: <admin email>`. The gateway maps that email to a verified account on `ADMIN_EMAILS` and runs the normal `routes/admin.ts` as it. Keep `ADMIN_EMAILS`: the gateway depends on it.
- **The public API has no `/api/admin`.** `api/src/app.ts` (`createPublicApp`) mounts only auth and profile; `/api/admin/*` is 404 there. Never mount `routes/admin.ts` on the public app again, and never trust `X-Admin-Actor` anywhere except inside `admin-gateway.ts`.
- **An admin delete keeps the row.** `DELETE /api/admin/users/:id` sets `users.status = 404` and ends the account's sessions; every user lookup filters `status <> 404`. Only Cleanup (`/api/admin/cleanup/*`, admin.xahabcse.me → Cardstock → System → Cleanup) restores the account or deletes it for good, profile images first. A signup with a deleted account's email gets `409 EMAIL_IN_USE` until then. Status values match the portfolio and NewsPortal: Active `1`, Inactive `-1`, Deleted `404`.
- **The app's `/admin` route** shows a plain "Page not found" (`app/src/pages/NotFoundPage.tsx`).
- **Changing an admin endpoint:** edit `api/src/routes/admin.ts` here, keep `api/test/admin-gateway.test.ts` green (`npm test` in `api/`), deploy by pushing `main`; then update the matching page in the portfolio repo (`Web/portfolio-admin-react/src/pages/cardstock/`, types in `src/lib/hub/types.ts`).
